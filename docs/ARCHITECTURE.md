# Архитектура

Модульный монолит: один Python-проект, один процесс сервера, но внутри — модули с закрытыми границами. Конвейер запускается отдельным процессом, чтобы остановка или падение сборки не роняли сервер.

## Слои

```
entrypoints   командная строка и HTTP: разбор запроса и сборка приложения
    ↓
pipeline      порядок этапов: соединяет модули, предметной логики нет
    ↓
modules       предметная логика, 21 модуль
    ↓
shared        ядро: пути, JSON, проверка цитат, общие части HTTP
```

`sdk` — открытый набор для доменных пакетов: шаблоны рисунков и роликов импортируют только его.

Стрелки только вниз. Сервер не импортирует `pipeline`, конвейер не импортирует FastAPI.

## Модуль

```
backend/glava/modules/<имя>/
  __init__.py   одна фраза: за что отвечает
  api.py        публичный вход: другие модули импортируют только отсюда
  module.py     встраивание в приложение: install(container, settings) и router
  router.py     HTTP-маршруты, если есть
  schemas.py    запросы и ответы HTTP, если есть
  …             внутренности, снаружи недоступны
```

| Модуль | За что отвечает |
| --- | --- |
| `source_text` | текст главы: страницы, единицы, таблицы |
| `errata` | сверка текста со сканом |
| `layer` | учебный слой: план, узлы, обогащение |
| `format_routing` | формат для узла |
| `tasks`, `illustrations`, `video` | задания, рисунки, ролики |
| `drawing` | холст и шаблоны рисунков |
| `course`, `simulations` | сборка курса и симуляторы в нём |
| `trust`, `review` | проверка своего слоя и чужого пакета |
| `library`, `books` | загруженные файлы и книги |
| `catalog` | главы, узлы, поиск |
| `publishing`, `access` | публикация курса, вход автора |
| `runs`, `metrics`, `llm`, `system` | запуски, расход, модели, состояние |

## Правила, которые проверяет тест

`backend/tests/architecture` падает, если:

- слой смотрит вверх;
- модуль импортирует внутренности чужого модуля, а не его `api.py`;
- зависимость модуля не записана в `backend/architecture.toml` или записана, но не нужна;
- между модулями появился цикл;
- в `api.py` есть имя, которым никто снаружи не пользуется;
- код импортирует пакет, которого нет в `pyproject.toml` прямо (пришёл вместе с чужим);
- вычисляет путь к репозиторию в обход `shared/paths.py`.

## Как разорвать круг

Список глав показывает идущий запуск и дату публикации, а запуски и публикации сами зависят от глав. Поэтому `catalog/ports.py` объявляет, что ему нужно (`ChapterStatus`), а `entrypoints/http/chapter_status.py` это даёт. Так же поступайте с новым кругом.

## Сделать новое

- **Модуль:** папка с `__init__.py`, внутренности, `api.py` с нужными именами, строка в `architecture.toml`. Если есть HTTP — `router.py`, `module.py` и строка в `MODULES` файла `entrypoints/http/app.py`.
- **Этап конвейера:** файл в `pipeline/steps`, команда в `entrypoints/cli.py`, промпт в `pipeline/prompts`.
- **Доменный пакет:** папка в `workspace/domain`, шаблоны импортируют `glava.sdk`.

## Остальное

`web` — React по функциям (`features/<имя>`), функция не импортирует другую функцию, общее лежит в `ui`, `lib`, `api`. Плеер курса `src/course` отдельный: у него свой вход и своя сборка (`vite.course.config.ts`) в один обычный скрипт, потому что с `file://` браузер не грузит модули. Он не берёт ничего из `app`, `features` и Mantine; с Python его связывают `data.js` (типы — `src/course/types.ts`) и `assets/course.js`, с симуляторами — узел `[data-interactive]` и `Simulations.mount`. В приложении курс показан в рамке: опубликованный снимок хранит плеер вместе с данными, и новый плеер не ломает старые курсы. `simulators` — отдельный JavaScript-проект; с Python связан файлами в `workspace/work` и собранным проигрывателем в `modules/course/assets/sim`.

Где какие данные: `workspace/work` — слои и этапы, `workspace/out` — курсы, `workspace/domain` — доменные пакеты. Другая папка данных задаётся переменной `GLAVA_ROOT`.
